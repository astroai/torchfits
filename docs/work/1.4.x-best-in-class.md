# Plan: 1.4.x — the FITS release to beat (2026-11-28)

Status: PROPOSED. Owner: maintainer. Scope: the whole 1.4.x line, starting
from the 1.4.0 release candidate on `main` (the 1.4 correctness wave,
streaming writes, native `where=`, fpack controls, scale and CFITSIO
hardening; see `docs/roadmap.md`).

**Goal.** By the last 1.4.x release, torchfits is the best FITS software on
every axis we can measure — performance, functionality, usability, docs and
reliability — against every earlier torchfits release and every other FITS
implementation, with the evidence published by torchfits-harness.

**Boundary.** 1.5 starts direct-to-GPU reads, torchfits' own tile codecs and
the work shared with other astronomy formats (heading to 2.0). Nothing in this
plan may need those. The 1.x read and write calls stay compatible; every
behaviour change ships with a note in `docs/compatibility.md`.

---

## 0. Definition of done (the 1.4.x exit gate)

The final 1.4.x tag ships only when all of these hold, each produced by one
harness command and published in its docs:

1. **Performance scorecard.** For every case in the harness matrix (§H2),
   torchfits is fastest, or within the measured noise floor of the fastest,
   against every comparator in §H1, on Linux x86_64 and macOS arm64, mmap on
   and off. Any case that is not #1 is listed with a measured cause and an
   accepted reason (for example "CFITSIO's serial HCOMPRESS encoder; own codec
   in 2.0").
2. **No regression versus any earlier release** (1.0 … 1.4.n−1) beyond noise,
   in time or peak memory, on any case.
3. **Feature matrix.** Every row of the FITS 4.0 coverage matrix (§F) is
   Supported or explicitly Out of Scope with a reason; no Partial rows.
4. **Correctness.** Bit-exact read parity with CFITSIO direct / fitsio /
   astropy on the full real-archive corpus (§H4); every file torchfits writes
   passes `fitsverify` with zero errors and reads identically in astropy,
   fitsio and CFITSIO.
5. **Usability.** Every task in the cross-library cookbook (§H6) has a
   torchfits recipe with no more lines than the best competitor's, and every
   error a user can trigger names the file, HDU, column or keyword involved.
6. **Docs.** Every public symbol, CLI flag, environment variable and exit code
   is documented once and tested (docs-contract); migration guides exist for
   each comparator; performance guidance is backed by scorecard numbers.
7. **Reliability.** Fuzzing and sanitizer lanes run in CI on every PR; native
   line coverage and public-surface coverage meet their targets (§R).

## 1. Performance workstream

Targets are relative to the best comparator per case. Every item lands with a
harness case (new if missing) and before/after numbers from the same host.

### P1 — must land in 1.4.x

| ID | Item | Today | Target |
|---|---|---|---|
| PF-1 | **Parallel tile decompression** for RICE/GZIP/HCOMPRESS/PLIO images (row bands of tiles on separate read-only handles, or a tile-range API over CFITSIO's decoders) | Serial per HDU | Near-linear to 4 threads on full reads and large cutouts; no loss on single-tile reads |
| PF-2 | **Parallel tile compression** on write (`write(compress=…)`, `compress` CLI, streaming image writer) | Serial per HDU; `-J` only across files | Near-linear to 4 threads; byte-identical output to the serial path for a fixed dither seed |
| PF-3 | **Remote partial reads beyond uncompressed 2-D**: compressed images fetch only the tiles a cutout needs; scaled images; cubes; tables with row windows, column projection and `where=` | Full download | Bytes fetched ≈ bytes needed + headers; concurrent Range requests; byte-range cache |
| PF-4 | **Small-call overhead**: tiny image read, header/key reads, `read_batch`, dataset `__getitem__` | Tiny read ≈ 30 µs; small float32 +7 % vs 1.3.3 | Tiny read ≤ fitsio; fast path for repeated small reads in ML loops |
| PF-5 | **VLA throughput**: bulk heap decode (no per-row Python objects), device gather | `varlen_*` slowest table family | ≥ fitsio and astropy on every `varlen_*` case |
| PF-6 | **Native `read_torch(where=)`**: align the torch and Arrow predicate dialects (literal coercion, unsigned, scaled) so it uses the native windowed scan | Windowed torch evaluation | Same results; native speed; memory = result + one window |

### P2 — should land

| ID | Item |
|---|---|
| PF-7 | `read_batch` / dataset prefetch: overlap opens and reads across files with a bounded in-flight window; parallel open path |
| PF-8 | `.fits.gz` random access: benchmark the gz index against fitsio/astropy, tune index spacing, cache across handles |
| PF-9 | Write throughput for uncompressed images and tables (large `pwrite` blocks, no extra copies, checksum fused with the write) |
| PF-10 | Header-heavy files: huge HISTORY/COMMENT blocks, 10 k-keyword headers, many-HDU listing (keep O(1) per HDU) |
| PF-11 | String columns: bulk decode for every encoding we accept, not only ASCII/UTF-8 fast paths |
| PF-12 | Memory: no transient double buffers on any read path (scaled, unsigned, byte-swapped); peak RSS ≤ result + one window |
| PF-13 | Import time and first-call latency (`import torchfits` without torch; first read) — publish and minimize |
| PF-14 | Thread scaling: no global serialization on any read/write path (measure 1/2/4/8 threads, same and different files) |

## 2. Functionality workstream (FITS 4.0 coverage)

### F — coverage matrix to close

| ID | FITS feature | Today | 1.4.x target | Prio |
|---|---|---|---|---|
| FN-1 | **Tiled table compression** (`ZTABLE`, FITS 4.0 §10.3; `fpack -table`) | Not read or written | Read (all column codecs) and write; streaming writer support; `compress`/`decompress` CLI | P1 |
| FN-2 | **64-bit `Q` heap descriptors on write** | Readers accept `Q`; writers emit `P` | Automatic `Q` when the heap exceeds 2 GiB; test past 2 GiB | P1 |
| FN-3 | **Streaming image writer** (`torchfits.image.writer()` or section writer), incl. tile-compressed and checksum | Images must fit in memory | Out-of-core mosaics/cubes; atomic publish; bounded memory | P1 |
| FN-4 | **In-place image section updates** (`write_subset` for uncompressed images) | Whole-file rewrite only | `pwrite`/mmap update of a region; checksum refresh; atomic semantics documented | P1 |
| FN-5 | **Random groups** (`GROUPS=T`, UVFITS) | Refused | Read: group parameters as a table + data as a tensor; write optional | P2 |
| FN-6 | **`A3DTABLE`** (legacy binary-table name) | Unsupported | Read as `BINTABLE` | P2 |
| FN-7 | **`INHERIT` convention** | Ignored | `read_header(..., inherit=True)` and HDU objects honour it | P2 |
| FN-8 | **String arrays with `TDIM`** | One string per row; TDIM lost through Arrow | Shaped read with `shape_cells=True`; TDIM kept on write | P2 |
| FN-9 | **Nested columns with nulls** | Written as VLA (lossy layout) | Fixed vector + `TNULL`/NaN; round-trip keeps TFORM | P2 |
| FN-10 | **Streaming table writer gaps** | No append-as-HDU, no `quantize=`, integer nulls need explicit `tnull` | All three supported | P2 |
| FN-11 | **Header conventions**: HIERARCH and CONTINUE round trip on write, long-string keywords, in-place header edits that reuse header padding | Partly covered | Full round trip, no file rewrite when space allows | P2 |
| FN-12 | **`verify`**: structural checks for `.gz`/`.bz2` and remote files; optional fitsverify-equivalent checks (keyword order, mandatory keywords, padding) | Local uncompressed only | Parity with fitsverify verdicts on the corpus | P2 |
| FN-13 | **FITS time standard columns** (`TIMESYS`, `MJDREF`, `TIMEUNIT`) → Arrow timestamps in interop (metadata only, no WCS) | Not interpreted | Opt-in conversion in `to_arrow`/`to_pandas`/`to_polars` | P3 |
| FN-14 | **Grouping convention** (`GROUPING` tables) | Not supported | Read helper listing members | P3 |

Out of scope (unchanged): WCS evaluation, units, catalog cross-match, source
finding, spectroscopy transforms.

### CLI parity

Every common task done today with fpack/funpack, imcopy, fitscopy,
fitsverify, the ftools `ftlist`/`ftcopy`/`fstruct`/`fthedit`, and STILTS
`tcopy`/`tpipe` (selection, projection, format conversion) has a torchfits CLI
equivalent that is at least as fast and documented in `docs/cli-recipes.md`
with the side-by-side command. Decide `imexpr` (expression CLI) here: either
spec it as part of this parity work or drop it from the backlog.

## 3. Usability workstream

| ID | Item |
|---|---|
| US-1 | **Error audit**: every user-triggerable error names file, HDU, column/keyword and the fix; typed exceptions everywhere (`HDUNotFoundError`, `UnknownColumnError`, `ColumnExistsError`, truncated-file errors); no raw CFITSIO status without a sentence |
| US-2 | **API consistency review** (`.cursor/skills/release-api-freeze-review`): one name per concept across `read`/`table`/`open`/datasets/CLI; keyword-only flags; same defaults on every path |
| US-3 | **Typing**: complete public type hints and stubs, `py.typed`, mypy-strict clean for users |
| US-4 | **Progress and cancellation** for long operations (streaming writes, remote reads, compress/decompress, verify on huge files): optional progress callback, KeyboardInterrupt leaves no partial outputs |
| US-5 | **Notebook ergonomics**: concise `repr` of `HDUList`/HDUs/tables/headers matching `torchfits info`; compressed HDUs show image geometry |
| US-6 | **Defaults review**: `mmap="auto"`, `decode_errors`, `shape_cells` (decide now whether 1.5 flips it), cache sizes, thread counts — each documented with its measured reason |
| US-7 | **Decide 2.0-bound contracts now** and document them: `shape_cells` default, `NOT (...)` with nulls (keep vs three-valued logic) |
| US-8 | **Platform reach**: decide Windows support (astropy and fitsio support it). If yes in 1.4.x: wheels, CI lane, LLP64 audit of native integer types |

## 5. Reliability workstream (§R)

| ID | Item |
|---|---|
| RE-1 | **Fuzzing in CI**: promote the wave-6 harnesses (random tables/images/mutations/hostile files) to a seeded CI lane plus a nightly long run; corpus of crashing inputs kept as regression tests |
| RE-2 | **Sanitizers**: ASan+UBSan lane over native tests, fuzz subset and CFITSIO backport tests on every PR (extend `sanitizer.yml`) |
| RE-3 | **Coverage targets**: native line coverage (harness `coverage-cpp`) and Python coverage published; public-surface coverage 100 % (already gated in the harness) |
| RE-4 | **Write validity**: every write path's output checked by `fitsverify` and read back by astropy, fitsio and CFITSIO in the harness |
| RE-5 | **CFITSIO upstreaming**: report torchfits-only fixes (GZIP-tile hang, NAXIS ≥ 100 overflow, IRAF long-path crash, HCOMPRESS encoder overflow, `in(out.fits)` thread race, output-buffer sizing) to HEASARC; drop each patch when an upstream release carries it |
| RE-6 | **CI proven on GitHub Actions**: wheel tests at the torch floor and `torch_tested`, nightly torch canary, macOS 3.15, cp311 and aarch64 — green before the first 1.4.x tag |

## H. torchfits-harness workstream

The harness is the referee; this plan fails without it.

| ID | Item |
|---|---|
| H1 | **Comparators**: astropy.io.fits, fitsio, CFITSIO direct (C driver, the raw ceiling), CCfits, EleFits (C++), fpack/funpack, fitsverify, STILTS and nom.tam.fits (Java) where installable from conda-forge or Maven, the Rust `fitsio`/`fitsrs` crates and Julia `FITSIO.jl` where installable. Each comparator gets a small driver per case; unavailable ones are listed, not silently skipped. Previous torchfits releases (1.0 … latest) are comparators too |
| H2 | **Case matrix**: images (dtypes, scaled, unsigned, 1-4 D, MEF, cutouts, strided), compressed images (every codec × quantize/dither × tile shape, read and write), tables (narrow/wide/mixed/strings/VLA/TDIM/ASCII/compressed tables, projection, row windows, `where=`, streaming read and write, mutations), headers, checksums, remote (HTTP Range, object stores), `.gz`, ML loaders (DataLoader workers, lazy vs eager), CLI commands vs their ftools/fpack/STILTS equivalents, import time, peak memory, thread scaling |
| H3 | **Methodology**: interleaved runs, enough repeats for a confidence interval, a measured noise floor per case (two runs of the same build), and a verdict per case (win / tie-within-noise / loss). The 1.4 RC showed run-to-run noise larger than some deltas; the scorecard must report it |
| H4 | **Corpus**: extend the full tier across missions and instruments — HST, JWST, SDSS, Gaia, DES, Euclid, Rubin data previews, Chandra/XMM event lists, Fermi, radio UVFITS (random groups), IRAF `.imh`, fpack-compressed tables — with bit-exact parity tests |
| H5 | **Scorecard publication**: one command produces `docs/benchmarks.md` tables, per-comparator win/loss counts, trend versus earlier releases, and the deficit list; CPU (Linux, macOS) and GPU (CANFAR) lanes |
| H6 | **Usability cookbook**: the common FITS tasks (open/inspect, read image, cutout, read table subset, filter, convert, write, compress, edit header, verify, append rows, build a DataLoader) implemented with each comparator; lines of code and wall time recorded |
| H7 | **Parity and replay**: keep upstream replays (fitsio, astropy, CFITSIO, CCfits, EleFits, qfits, sfitsio) current; add fitsverify cross-checks for every torchfits-written fixture |
| H8 | **PR gate**: a bounded benchmark subset that runs on every torchfits PR and flags regressions beyond the noise floor |

## Sequencing

Each step is a 1.4.x release; every release passes all current gates and the
harness scorecard shows no regression.

1. **1.4.0** — current release candidate (correctness wave, streaming writes,
   native `where=`, fpack controls, scale and CFITSIO hardening). Prove CI on
   GitHub Actions (RE-6); land harness H3 methodology and H8 PR gate first so
   every later step is measured.
2. **1.4.1 — native throughput**: PF-1, PF-2, FN-2, PF-5, PF-6.
3. **1.4.2 — out of core and remote**: FN-3, FN-4, PF-3, FN-10.
4. **1.4.3 — format completeness**: FN-1, FN-5, FN-6, FN-7, FN-8, FN-9, FN-11.
5. **1.4.4 — usability and CLI parity**: US-1…US-6, CLI parity, FN-12,
   `imexpr` decision, H6 cookbook.
6. **1.4.5 — docs and reliability**: DO-1…DO-7, RE-1…RE-5, remaining P2/P3,
   H1/H4/H5 complete, then the §0 exit gate.

Decisions needed from the maintainer before 1.4.1: US-7 (`shape_cells`
default, `NOT` null semantics), US-8 (Windows), `imexpr` keep/drop, the H1
comparator list (which Java/Rust/Julia lanes are worth maintaining).
